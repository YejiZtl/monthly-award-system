# 会议终审更新（0.7.0）

工作流程：工作台 → 申报与核对 → 初审 → 复审 → 终审 → 导出。

初审、复审共用原审核员账号，分成两个待办列表。初审通过才进入复审；复审通过才进入本月会议表。系统不校验两次操作是否为不同的人，按实际分工使用。

终审直接展示当月奖金核算表，支持投影模式、查看原表和证明、调整应发金额、填写其他/权重/实发及修改备注。查看材料后点击“返回10月奖金核算表”回到原会议页面。会议数据保存后可离开再回来继续。其他、权重、实发是独立填写项，不自动相乘或计入应发。

会议讨论完毕点击“确认会议结果，完成终审”，此时不生成文件；到“导出”选择数值版或公式版才下载并归档。确认后继续修改会使确认失效，需要重新终审。已归档文件不会改变。同月同部门或同名项目替换须重新初审和复审，复审时明确确认替换，旧历史文件保留。

旧数据：未审核记录进入初审；以前已审核记录保留并进入会议表，不补造初审记录。历史导出保留，今后新导出须先确认会议结果。仍保留此前隐藏A、B列、取整及上传重试等改进。

## 在公司 Mac 更新

将“员工月奖系统_会议终审更新包_20261021.zip”复制到 Mac 桌面，在无人在申报时更新。建议先创建虚拟机快照。以下命令在 Mac 终端执行（使用公司内网）：

```bash
scp "$HOME/Desktop/员工月奖系统_会议终审更新包_20261021.zip" awardadmin@<SERVER_IP>:~/monthly-award-meeting.zip
ssh -t awardadmin@<SERVER_IP> 'set -e; stage=$(mktemp -d "$HOME/monthly-award-meeting.XXXXXX"); /opt/monthly-award/.venv/bin/python -m zipfile -e "$HOME/monthly-award-meeting.zip" "$stage"; cd "$stage/员工月奖系统"; sudo bash infra/upgrade_vm_meeting_20261021.sh'
```

脚本核验文件后备份代码、配置和数据库，保留账号密码、上传材料、历史文件与原网络配置。备份路径为 /var/backups/monthly-award/meeting-20261021-时间。启动验证失败时恢复旧代码和配置；新增表保留。更新后产生业务数据时不要直接恢复旧数据库，以免丢失新记录。

## 检查更新成功

在 Mac 终端输入：

```bash
ssh awardadmin@<SERVER_IP> 'curl -fsS http://127.0.0.1:8000/health'
```

应显示 status 为 ok、version 为 0.7.0。浏览器强制刷新（Mac：Command+Shift+R），侧栏应出现六个阶段。用测试申报检查初审、复审各自待办，终审查看材料并返回，会议修改保存，确认后再导出。

本次仅在本地隔离环境验证，尚未部署公司服务器。脚本未在真实 Linux 服务器执行；公司投影设备的实际分辨率和网络速度需现场确认。测试记录见 MEETING_VALIDATION_20261021.txt。
